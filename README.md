# LocalAutonomousAI (Windows, internet-connected)

A desktop chat app with a **local** LLM (llama.cpp) fine-tuned from synthetic data
generated by Claude. Claude is used only at build time as the teacher; it is never
bundled or called by the app. At runtime the app is online-first: it downloads the
model on first run, can ground answers with live web search, and checks GitHub
releases for updates. If the network is down, chat still works with the local model.

## 1. Build the model (Python 3.11, NVIDIA GPU)
```bash
cd pipeline
pip install -r requirements.txt
export ANTHROPIC_API_KEY=...            # teacher only
python 01_data/generate_dataset.py --calls 20
python 01_data/validate_dataset.py
python 02_train/train_qlora.py --rank 16
python 02_train/merge_adapters.py
```
```powershell
.\03_quantize\quantize.ps1 -LlamaCpp C:\src\llama.cpp -Quant Q4_K_M
.\03_quantize\verify.ps1  -LlamaCpp C:\src\llama.cpp -Model .\output\gguf\custom_assistant_q4_k_m.gguf
```
Host the resulting `.gguf` (e.g. on Hugging Face) and put its https URL in
Settings -> Model download URL. Until then the app defaults to the stock Qwen2.5-3B GGUF.

## 2. Run / package the app (Windows, Rust, Node 20+, CMake, VS Build Tools)
```powershell
cd app
npm install
npx tauri icon path\to\logo.png         # generates src-tauri/icons/icon.ico
npm run tauri dev
npm run tauri build -- --target x86_64-pc-windows-msvc            # CPU
npm run tauri build -- --target x86_64-pc-windows-msvc --features cuda   # NVIDIA (needs CUDA toolkit)
```

## 3. Voice, vision and video (sidecar tools)
Put these Windows builds in `%APPDATA%\com.localautonomousai.desktop\tools` (or on PATH):
`ffmpeg.exe`, `whisper-cli.exe` (whisper.cpp release), `llama-mtmd-cli.exe` (llama.cpp release).
Then open **Eyes & ears** in the app and download the speech, vision and projector models.
- Hearing: microphone -> whisper.cpp. Speaking: Windows built-in voices (SAPI).
- Seeing: screenshot or image -> vision model. Watching: a local video file is sampled
  (frame every N s + transcribed audio) into a time-coded timeline attached to the chat.
  It is sampled, not frame-perfect, and DRM streams (Netflix etc.) cannot be read.

## 4. Self-update through GitHub (human-approved)
Settings -> repository `owner/repo`; open **Self-update**, save a fine-grained token limited to that repo
(Contents + Pull requests: read/write; stored in Windows Credential Manager). The assistant drafts a change,
you review the diff, and approval opens a **draft PR** on an `ai/update-*` branch. There is no code path that
pushes to the default branch or merges. Editable paths: `app/src`, `app/src-tauri/src`, `pipeline`, `README.md`;
`github.rs`, `proposals.rs` and `commands_github.rs` are protected.

## 5. Learning from users (opt-in) and the server
`server/` is a small FastAPI service you host (HTTPS). Set its URL in Settings -> Learning programme.
On first launch users see a notice and must click **Share** before anything is sent. Only answers rated 👍 are
uploaded (question + reply), after automatic redaction of emails, phones, keys, IPs and user folders; videos, audio,
screenshots, images, settings, tokens and video chats are never sent. Users can withdraw and delete their data
from Settings. Training is periodic, not live: `merge_contributions.py` -> `validate_dataset.py` -> retrain.
Read `server/README.md` for your operator duties (privacy policy, deletion requests, GDPR).

## 6. Media size and code quality
- No file-size limit on videos: ffmpeg streams from disk. Long films take longer; raise *max frames* for detail.
  Very long timelines are condensed per question (relevant scenes + an even overview), never cut off.
- Code skills: the pipeline now defaults to Qwen2.5-Coder-7B, 4096-token samples, rank 32, 7 coding categories,
  syntax checks on every Python/JSON block, and `validate_dataset.py --execute` to run the generated self-tests
  (use a VM/container: it executes model-written code). The runtime default is Qwen2.5-Coder-3B; for a 7B model
  set the Model URL in Settings. A local 3B-7B model will not match a frontier model - expect it to be solid on
  routine code, weaker on large or novel problems.

## 7. Recap maker (no cloud AI)
Inspired by the web app *movies--tv--recaps--maker--with--ai--app*, which sends the video to Google Gemini to pick moments.
Here **everything runs on-device**: the local vision model describes sampled frames, whisper.cpp transcribes dialogue,
the local LLM rates every moment 0-9 for story importance, and loudness / scene-cut / speech-density signals break ties.
The film is split into one bucket per wanted clip and the best moment of each bucket is kept, so the recap follows the
story from start to finish; ffmpeg cuts and joins the clips (no file-size limit), and Windows speech can narrate it.
Open **Recap maker**, pick a file, describe the plot (this helps), choose the length, press Create.
Honest limits: it sees sampled frames, not every frame, so picks are less precise than a model that watches the whole
video natively; more *frames to analyse* improves quality but takes longer. The UI is English only (the original has 6 languages).
